# ADR: AAC/MP4書き換えを単一の最終出力生成へ変更する

## 状態

採用

## 背景

従来のAAC書き換えは、入力ファイル全体を一時ファイルへコピーした後、
`MP4Modify()`で一時ファイルを変更し、最後に`MP4Optimize()`で再度全体を
書き換えていた。入力ファイルが外部ディスクやネットワークボリュームに
ある場合は、さらにファイルシステム間コピーが発生する可能性があった。

## 決定

- 入力ファイルは読み取り専用で開き、`MP4Modify()`を入力ファイルに対して
  使用しない。
- `MP4Optimize()`相当の出力生成処理で、各チャンクをメモリ上に読み込んだ
  時点でAACの`global_gain`変更を適用する。
- ReplayGainタグの変更も出力生成前にメモリ上のMP4構造へ反映する。
- 最終出力は入力ファイルと同じディレクトリの一時ファイルへ生成し、成功後に
  renameする。これにより通常は同一ファイルシステム内の原子的な置換になる。
- AAC変更位置はサンプル単位の小さなランダム書き込みではなく、チャンク単位の
  読み書きにまとめる。

## 理由

入力全体の事前コピーと、`MP4Modify()`後の追加書き換えをなくし、音声データを
一度読み、一度出力する経路にするため。入力ファイルを途中状態にしないため、
書き換え失敗時は最終一時ファイルを破棄して元ファイルを保持できる。

## 影響

- 通常の書き換えで発生する全体I/Oが減る。
- 一時ファイルは`/tmp`ではなく入力と同じディレクトリに作成される。
- MP4再配置処理は同梱mp4v2の実装を拡張しているため、MP4のチャンク順序と
  複数トラックの出力順序を既存の`MP4Optimize()`に合わせる。
- 完全な実行テストには`3rdparty/faad2`サブモジュールが必要だが、現在の作業
  ツリーでは同ディレクトリが空であり、フルビルドは別途復元が必要である。
